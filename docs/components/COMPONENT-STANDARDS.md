# Component Standards

All Borgi components must define purpose, anatomy, variants, sizes, states, interaction, content rules, responsive behavior, accessibility and token mapping.

## Required states
Default, hover, focus-visible, pressed, selected, disabled, loading, success, warning and error where applicable.

## Accessibility
- Keyboard operable with visible focus.
- Semantic HTML first.
- Form controls have persistent labels and associated errors.
- Icon-only controls have accessible names.
- Touch targets are at least 44×44 CSS px.
- Color is never the only status indicator.

## Core inventory
Button, icon button, input, textarea, select, combobox, checkbox, radio, switch, date picker, time picker, calendar, card, table, tabs, badge, avatar, tooltip, popover, modal, drawer, toast, empty state, skeleton, pagination, breadcrumb, navigation and charts.

## Governance
New variants require a real repeated use case. Product screens consume shared components and tokens instead of local copies.
